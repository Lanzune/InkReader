## 文档规则

1. **一个功能模块一个文档**：模块文档写目的、接口、边界、任务、测试和退出标准，不把所有内容堆在一个总文档里。
2. **阶段计划只展开下一步**：M0/M1/M2 写细；M3–M7 先保留在路线图中，进入阶段前再展开，避免过早承诺。
3. **决策有 ADR**：语言、插件运行时、EPUB/PDF 引擎、网络权限等不可逆或高成本决策，必须有 ADR。
4. **状态看板实时更新**：每个阶段开始/结束更新 `07-status.md`；完成一个模块必须更新文档和测试记录。
5. **以 Markdown 为源**：报告 DOCX 由 Markdown 生成，不直接编辑 DOCX。
6. **不记录秘密**：签名密钥、GitHub token、设备序列号等不进入仓库。
