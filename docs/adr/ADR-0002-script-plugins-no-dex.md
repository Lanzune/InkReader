# ADR-0002：第三方插件使用 QuickJS，不加载 DEX/原生代码

**状态：** Accepted  
**日期：** 2026-11-05

## 背景

需要类似 VS Code 的可扩展性，但 Android 上动态加载 DEX/APK 会带来安全、版本、签名、Google Play 政策和崩溃隔离问题。主应用应保持“硬内核”。

## 决策

- 首版第三方插件运行在 QuickJS 沙箱中。
- 插件包为 `.inkp`（manifest + JS + 资源），不包含 DEX/JAR/`.so`。
- 插件只能调用能力白名单 API，不暴露 Context/Uri/File/Intent。
- 插件在专用线程运行；v1.1 迁移独立进程。
- 原生扩展通道（独立插件 APK + AIDL Service）放 v2，不在主应用内加载代码。

## 替代方案

| 方案 | 不选原因 |
|---|---|
| 应用内 DexClassLoader | 动态代码加载、版本锁定、崩溃/权限风险；政策风险 |
| WebView 承载 JS | 内存/缓存/桥接面大，和轻量目标冲突 |
| Lua | 可行，但开发者生态和 JS 熟悉度较低 |
| 只做静态内置功能 | 不满足可扩展目标 |

## 后果

- 插件不能做任意原生 UI、格式引擎或页面动画；这些走 v2 原生通道。
- QuickJS 原生库需要 16 KB 对齐，并增加约 1–2 MB/ABI。
- 沙箱不是绝对安全边界；信任模型和隔离要在 UI 中说明。
- API 必须版本化、异步、JSON 化，便于未来迁移到进程。

## 验证

- M1 跑通主题/命令插件。
- M6 做超时、内存、恶意包和版本拒绝测试。
- 16 KB 模拟器/设备验证。
