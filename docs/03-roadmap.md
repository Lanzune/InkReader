# 阶段路线图

> 基线原则：每个阶段只做当前阶段需要的事；下一阶段开始前，上一阶段必须有可运行产物和验收记录。

## 总览

| 阶段 | 时间（单人全职） | 主题 | 主要产物 | 退出标准 |
|---|---|---|---|---|
| M0 | 1 周 | 骨架与环境 | Gradle 工程、目录、文档、git、环境配置 | CLI 构建 debug APK 成功 |
| M1 | 2–3 周 | 垂直切片 | 内核最小 API、QuickJS 宿主、TXT、阅读视图、主题/命令 | 真机可打开 TXT、翻页、切换插件主题 |
| M2 | 2 周 | TXT 与阅读核心 | 完整 TXT、设置、进度、日夜、最近阅读 | 100 MB TXT 可用，进度可恢复 |
| M3 | 3–4 周 | EPUB | ZIP/OPF/XHTML、目录、封面、基础样式 | 语料库 ≥95% 打开，无丢字/错页 |
| M4 | 2 周 | PDF 与文档格式 | PDF 页面/缩放/夜间；HTML/Markdown | 常见 PDF 可读，异常文件友好报错 |
| M5 | 2 周 | 阅读体验 | 亮度、主题、覆盖/淡入/折页、命令面板 | 中端机 60 fps，低端机有降级 |
| M6 | 2 周 | 插件 SDK 与安全 | manifest、能力、示例插件、安全模式、文档 | 示例插件独立安装运行；恶意/超时被隔离 |
| M7 | 2 周 | 硬化与发布 | 测试矩阵、体积、16 KB、签名 APK、发布说明 | 体积 ≤12 MB，P0 清零，真机验收 |
| 缓冲 | 2–4 周 | 修复与兼容 | 修复、文档、发布候选 | 可交付 v1.0 |

总计约 **18–22 周**（含缓冲）。MVP 可压缩到 10–12 周，但不应压缩插件边界和测试。

## 阶段依赖

```text
M0 ──► M1 ──► M2 ──► M3 ──► M4 ──► M5 ──► M6 ──► M7 ──► v1.0
              │
              └──► M5 的视觉规范可以并行设计，但代码必须等 M2
```

- M1 是 Go/No-Go 闸门：插件边界和阅读主链路必须先成立。
- M3 必须在 B0 真机验收之后开始，避免 EPUB 细节掩盖内核问题。
- M5 的翻页动画不能阻塞 M3/M4 的格式工作。
- M6 的 SDK 文档只能在至少两个真实插件跑通后定稿。

## 两个开发者

| 角色 | 主要模块 |
|---|---|
| A：内核/平台 | kernel、plugin-host、storage、PDF、质量 |
| B：阅读/格式 | reader-engine、TXT、EPUB、UI 阅读体验 |
| 共同 | 接口评审、格式语料、真机清单、发布 |

两人并行预计 **12–15 周**，但仍需 M1 串行完成。

## MVP 与 v1.0 的差别

**MVP（10–12 周）**

- TXT + EPUB + PDF 基础
- 主题、日夜、亮度、滑动/覆盖
- 插件主题/命令
- 无折页、无 HTML/MD、无完整 SDK 文档

**v1.0（18–22 周）**

- MVP + HTML/MD、折页、命令面板、SDK/示例/安全模式、完整测试和发布流程

## 每个阶段结束必须做

1. 更新 [状态看板](07-status.md)；
2. 更新对应模块文档和验收记录；
3. 运行质量门槛中的自动检查；
4. 提交并打阶段标签；
5. 给项目所有者一份真机验证清单；
6. 通过后才进入下一阶段。
