# 图片预加载（0.8.1）

## 参考

用户提供的手机阅读器录屏里，图片和文字是作为完整页面一起出现的，没有“先出文字、再弹出图片”的过程。

当前实现的问题：

- `LazyEpubDrawable` 在 `draw()` 时才解码位图
- 图片解码发生在 UI 绘制路径
- 页面先出现文字/空位，图片随后出现

## 修改

- 新增 `AsyncPageImage` 接口
- `LazyEpubDrawable` 改为：
  - 构建时只读图片边界
  - `preload()` 在线程池解码
  - `draw()` 不再解码
  - `isReady` 表示位图/失败状态
- `ReaderSurfaceView`：
  - 当前页绘制前检查图片是否 ready
  - 未 ready 时不绘制半成品页面
  - 预加载当前页和下一页图片
  - 翻页/文章跳转时更新预加载范围
- 线程池限制为 2 个解码线程，避免多图同时解码挤占 CPU
- 图片仍按目标尺寸采样，控制内存

## 行为

- 进入页面时图片已解码或正在同一页预加载
- 不再先显示页面、再在绘制中解码图片
- 下一页图片在当前页阅读期间预取
- 解码失败时页面继续显示，不阻塞

## 待真机验证

本次修改完成后手机 adb 处于 `unauthorized`，无法安装/截图验证。

需要用户：

1. 解锁手机
2. 在“USB 调试”授权弹窗点“允许”
3. 重新执行 `adb devices` 确认状态为 `device`

之后验证：

- 打开带多图的页，页面不应先出现图片空位再弹出
- 连续翻页，图片应随页面一起出现
- 大图页面无长时间白屏/ANR
