# 模块 03：TXT 格式

**代码：** `formats/txt`  
**阶段：** M1（最小）/ M2（完整）  
**状态：** M1 最小版已实现（UTF-8 + BOM、单章节）

## M1 已验证

- 严格 UTF-8 解码，去除 BOM
- 单章节 `BookDocument`
- JVM 单元测试：BOM、扩展名探测
- 编码探测、章节索引、大文件、Locator 留到 M2

## 目的

可靠地打开各种来源、编码和大小的纯文本小说，提供章节识别、稳定定位和低内存读取。

## 处理链路

1. 读取 BOM 和前 64 KB 采样
2. 严格 UTF-8 解码，失败后尝试 UTF-16/GB18030/Big5
3. 无法确定时提示用户手动选择编码
4. 扫描章节标题，建立字符/字节偏移索引
5. 按块读取，不把整本文件读入内存
6. 输出 `BookDocument`（Reflowable）
7. 通过 Locator 恢复章节 + 字符位置

## 章节规则

默认支持：

- `第[一二三四五六七八九十百千万零〇0-9]+[章节回卷部篇]`
- `Chapter\s+\d+`
- `序章`、`楔子`、`后记`、`尾声`

允许插件覆盖规则；规则错误不能导致无法阅读，最多回到“无章节”模式。

## 边界

| 场景 | 要求 |
|---|---|
| 100 MB TXT | 首屏 ≤3 s，不 OOM |
| 无 BOM 的 GBK | 自动识别或提示切换 |
| 大段无换行 | 不阻塞主线程；按块切分 |
| 文件被删除/权限丢失 | 友好错误，不崩溃 |
| 编码错误 | 不静默输出乱码 |

## 测试

- UTF-8/UTF-16LE/BE/GB18030/Big5 样本
- BOM/无 BOM、CRLF/LF
- 章节正则误匹配/漏匹配
- 超大文件首屏、随机跳转
- 损坏/空文件
- Locator 恢复

## 退出标准

- 主流中文 TXT 打开不乱码
- 章节可跳转，进度可恢复
- 100 MB 文件不崩溃
- 编码/章节规则可被插件覆盖
